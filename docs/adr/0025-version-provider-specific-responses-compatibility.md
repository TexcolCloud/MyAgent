# Version provider-specific Responses compatibility contracts

DeepSeek Responses is supported through a strong, versioned Provider Compatibility Contract in the immutable Pi runtime contract captured by each Model Profile Revision and Run snapshot. The durable top-level Invocation Protocol remains `pi_ai`; its nested Provider API is `openai-responses`, and for the project-owned `pi/deepseek:deepseek-v4-flash-responses` Compatibility Variant, `deepseek-responses-v1` emits the documented minimal Responses request shape and adds `tool_choice: "required"` only for the tool-capability verification probe. The contract is selected only by that explicit native candidate, never inferred from Base URL or model name; remote discovery of `deepseek-v4-flash` and fresh verification remain required. It does not rely on unsupported fields being ignored. Automatic fallback to Chat Completions is forbidden, existing revisions and snapshots are immutable, unknown contract versions fail closed, and a model attempt with multiple distinct Tool Calls fails before any call can be proposed or executed. Contract or stream-shape rejection is reported as the existing redacted `model_protocol_error`; an otherwise completed probe without exactly one valid Tool Call is `tool_call_unsupported`. Deterministic loopback tests lock the Pi serializer, gateway route, request shape, continuation, and malformed-stream boundaries; an opt-in live smoke verifies the tool probe and a no-Tool Run without exposing credentials or running a real Tool.
